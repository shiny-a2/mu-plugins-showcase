# Competitor brand evidence candidate

Prepared 18 November 2026. This change has not been activated on the store or collector host.

Managers need to distinguish repeated availability changes from the number of distinct watch models involved. The candidate report counts unique factory references by brand and retailer, shows how many match the store's own catalogue, and marks brands the store does not carry. A retailer drilldown keeps the dated reference and price checks available. Sorting by those reference counts is covered by interactive tests.

The collector candidate adds a watch-only public Banimode source. It validates category pages, price units and stock fields, keeps requests bounded, and labels incomplete coverage instead of presenting it as a complete inventory. Its public catalogue was sampled locally, but observed stock changes remain only possible sales signals; neither orders nor physical inventory are known.

Validation passed the focused PHP and Python suites and four mobile/desktop light/dark interaction states. A bounded sample audit of 44 configured rival sources returned 38 readable samples; other results included access rules, a timeout and audit limits. Full-source reliability and authenticated live rendering still require checks after an approved release. The cold report cache has not been timed in production for this candidate.
