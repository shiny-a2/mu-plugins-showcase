# Faster product bulk editing and visible save failures

The product bulk editor retains the operator's 100-row setting, with smaller page-size choices still available. Ordinary grid reads and product edits avoid broad refresh work that slowed the shared administration system. Concurrent editor requests no longer wait behind an unused session lock. Attribute choices are prepared for the columns currently in use, while the full set of columns remains available in settings. The large reference list can be searched when needed in filter and bulk panels, preserving selected choices across searches. If a save request fails, the screen shows a persistent warning and offers a deliberate table reload so the operator can check the stored value.

Isolated checks passed for page-size limits, authorized request scope, session release, failed-save feedback, reference search and selection, and compatibility updates against the installed editor version. The scoped live files matched the prepared source; the editor remained active, and the new assets and public home page returned successful responses. In read-only command-line checks, editor settings construction took 5.067 seconds before the attribute update and 0.213 seconds afterward. Screen rendering later fell from 4.573 to 0.719 seconds, while HTML output fell from 11.4 MB to 2.7 MB after reference search was added. The restored setting returned 100 rows in 13.335 seconds in a separate simulated grid request. These are internal diagnostics, not browser loading times. No real product was changed for testing, so authenticated saves remain unverified.
